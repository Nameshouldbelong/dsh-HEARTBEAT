## 实测发现（含三个改写契约的事实）

1. **max_tokens=1 的请求完全不参与 Kimi coding 端点的前缀缓存**（连发双 miss），max_tokens=16/100/1024 均正常命中 → ping 采用 max_tokens 钳到 ≤1024 策略（原 B5 契约的 max_tokens→1 作废）。
2. **ping 必须携带与真实请求相同的注入**（顶层 cache_control{ttl:1h} + metadata.user_id 亲和键）：无顶层 cache_control 只读 5m 池，且无亲和路由会被负载均衡打散 → 超 5min 必 miss。
3. **dsh 插件包必须 exports["./client"]**（client-modules 注册器强制），缺失时整个 dsh web 启动失败（required plugin did not activate）。
